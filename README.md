# Compliance Assistant

**AI-assisted source-code review for security and regulatory control gaps.**

Compliance Assistant is a prototype intended to help developers and reviewers identify potentially relevant security and privacy issues in application code, understand why a finding may matter, and plan remediation. It is a decision-support tool—not a compliance certification service, legal opinion, penetration test, or substitute for an independent audit.

> **Important:** Findings generated by automated or AI-assisted analysis are hypotheses requiring verification against source code, runtime configuration, data flows, compensating controls, and the applicable framework version. A report is not proof that an organization is compliant or non-compliant.

## Project status

This repository was empty when inspected for this update. Application source code and test files were not available in the repository to verify or publish. This initial release therefore does not invent implementation details, test counts, accuracy figures, or production-readiness claims.

## Intended use

- Source-code review for potential security and privacy control gaps.
- Mapping candidate findings to relevant framework requirements for reviewer consideration.
- Structured findings with affected component, observed evidence, risk rationale, confidence, and suggested remediation.
- Human review and follow-up validation.

These are intended capabilities; this documentation and sample report do not independently establish that every capability is implemented or validated.

## Sample audit result

The repository includes an original report for **Bundled Sample Systems**, dated May 9, 2026. It states a PCI-DSS payment-processing audit scope and lists PCI-DSS, GDPR, and HIPAA as frameworks.

- [Open the sample audit PDF](results/sample-audits/2026-05-08-bundled-sample-systems.pdf)
- [Read the artifact review and interpretation](results/sample-audits/README.md)

The PDF reports five candidate findings involving CVV logging, unencrypted payment transmission, PAN logging, hardcoded/plaintext credentials, and exposure of payroll SSN/salary data. These are **reported observations from the sample artifact**, not independently reproduced findings or formal compliance determinations.

**Provenance note:** The PDF identifies its analysis engine as IBM watsonx.ai / granite-34b-code-instruct. This provenance is retained as printed in the source artifact. It should not be silently relabelled as a Gemini-generated report or assumed to represent the current application configuration.

## Evidence and claims policy

1. Distinguish static code observations from runtime behavior and organization-wide compliance conclusions.
2. Include relevant code locations and explain the reasoning for every finding.
3. Record framework name, version, requirement identifier, and mapping rationale.
4. Label model-generated conclusions as candidate findings until a qualified reviewer validates them.
5. Do not publish accuracy, precision, recall, cost savings, or test-count claims without a documented evaluation protocol and reproducible results.
6. Do not predict fines, legal liability, processing suspension, or regulatory outcomes from a code snippet.
7. Record false positives, uncertainty, scope exclusions, and reviewer decisions.

See [Audit interpretation and claims policy](docs/AUDIT_INTERPRETATION.md) and [Methodology and validation](docs/METHODOLOGY.md).

## Limitations

- Automated source review cannot establish organization-wide PCI-DSS, GDPR, or HIPAA compliance.
- Applicability depends on the organization, data, processing purpose, architecture, contractual role, jurisdiction, and audit scope.
- Source-code findings alone do not establish exploitability, breach occurrence, regulatory liability, or a penalty.
- A recommendation is not proof that a control has been implemented or tested.
- The included PDF is a sample output and has not been independently re-performed as part of this repository update.
